2. Why Qwen fits Eclipse

The target is not ordinary image captioning. Eclipse wants machine-readable observations: who is present, what changed, what action occurred, what object was involved, when it happened, and how confident the model is.

Alibaba's current visual-understanding documentation recommends qwen3.7-plus as the flagship visual model and documents image/video understanding, a 1M context window, videos up to 2 hours / 2 GB, function calling and built-in tools. The same documentation says qwen3.6-flash can be used later to reduce cost while retaining a similar feature set.

Video / Images→ Frame + Scene Preprocessor→ Qwen Vision→ Structured Visual JSON→ Relationship Graph→ FICTION

4. Two-pass mining strategy

Do not send every frame of a long clip to the most expensive model. Use a cheap/coarse pass to locate candidate intervals, then a dense analysis pass around those intervals.

PassPurposeExample output
Pass A: discoveryFind interesting time windows and major visual events.00:12.4–00:15.8 = expression/action change
Pass B: forensicAnalyze selected frames or short windows in detail.subject, pose, expression, object, interaction, confidence
Pass C: normalizationConvert provider-specific output to Eclipse's canonical schema.VisualObservation JSON

6. The important separation: perception vs. interpretation

VISION

Question: What happened?

Detect characters, actions, expressions, poses, objects, camera events, temporal changes, text and interactions.

RELATIONSHIP LAYER

Question: How do the observations relate?

Convert raw observations into subject → action, subject → object, expression → event, and frame → timestamp relationships.

FICTION

Question: What does this mean for the narrative?

Apply character behavior masters, story structure, bindings, dials, duet patterns and narrative rules.

7. Qwen API integration

Alibaba documents an OpenAI-compatible interface for Qwen vision models. The basic migration pattern is to change the API key, base_url, and model name. Region-specific endpoints exist for China (Beijing), Singapore, Japan, US (Virginia), and Hong Kong. 

from openai import OpenAI
import os

client = OpenAI(
    api_key=os.getenv("DASHSCOPE_API_KEY"),
    base_url="https://<WorkspaceId>.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1"
)

response = client.chat.completions.create(
    model="qwen3.7-plus",
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "video_url",
                    "video_url": {
                        "url": "https://example.com/clip.mp4"
                    },
                    "fps": 2
                },
                {
                    "type": "text",
                    "text": "Return JSON describing the visual events and their timestamps."
                }
            ]
        }
    ],
    response_format={"type": "json_object"}
)

The exact regional base URL and workspace identifier must come from the Alibaba Cloud Model Studio console for the region/account being used. Do not paste API keys into client-side HTML.

8. Video sampling

Alibaba's current Qwen visual-understanding examples show direct video input through the OpenAI-compatible interface and a configurable fps sampling parameter. Their documentation explains that this controls how frames are extracted from the original video so the model can reason about sequence, duration, and dynamic changes. 

coarse discovery:
    fps = 0.5–2

candidate window:
    extract only around detected events

dense analysis:
    fps = 2–10 depending on motion and task

final:
    store timestamps + normalized observations

The exact sampling rate should be task-dependent. Fast motion may need denser sampling; static dialogue or composition analysis usually does not.

9. Structured output

Qwen Model Studio currently documents JSON mode through response_format: {"type":"json_object"}. The documentation also states that the system or user message must include the word “JSON” for this mode. 

{
  "response_format": {
    "type": "json_object"
  }
}

For Eclipse, structured output should be mandatory. Free-form prose should be treated as a fallback/debug mode, not as the canonical mining format.

12. Eclipse-specific mining targets

These should be represented as explicit detectors rather than one giant prompt.

Character detection
identity candidate, screen position, visibility, occlusion
Pose
standing, sitting, turning, leaning, gesture, locomotion
Expression

Interaction
gaze, proximity, contact, object use, response relationships
Camera
shot size, angle, cut, pan, zoom, framing changes
Temporal events
entry, exit, transformation, pose change, expression change, object change
Text/OCR
signs, captions, labels, UI, props, written dialogue
Visual composition
character placement, foreground/background, dominant objects, scene layout

14. Security

Never put the Qwen API key in browser JavaScript.
Use a small local/server-side API bridge: browser → local backend → Qwen. The browser should only know your local endpoint. 
Browser
   │
   │ POST /api/vision
   ▼
Local Eclipse backend
   │
   │ Authorization: Bearer <DASHSCOPE_API_KEY>
   ▼
Alibaba Cloud Model Studio

15. Recommended first prototype

  1. Build a local Qwen adapter using the OpenAI-compatible interface.
  2. Upload one short clip.
  3. Ask for only timestamped visual events in JSON.
  4. Normalize the response into the canonical VisualObservation schema.
  5. Render those observations as nodes in the relationship editor.
  6. Only then connect the output to FICTION.
Design principle: the vision model is the sensor, not the author. Qwen observes the visual material. Eclipse decides how those observations become relationships, behavior evidence, and eventually narrative.
