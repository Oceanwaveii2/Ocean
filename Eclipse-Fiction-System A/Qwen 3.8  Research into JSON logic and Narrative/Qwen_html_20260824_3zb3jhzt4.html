System Overview

This documentation describes a sophisticated narrative modeling system that transforms character references into executable behavioral programs for LLMs. The system prevents common AI narrative failures through:

Core Innovation: A "behavioral compiler" that separates author-only reference priors from native runtime expression, preventing AI drift and reference leakage while maintaining consistent character voices.

Key Features

  • Reference Firewall: Prevents characters from referencing their source material (e.g., "acting like Stewie Griffin")
  • Identity Axioms: Hard-locked character identity rules that cannot be violated
  • Behavior Trees: Game-AI style decision-making structures
  • Utility AI: Scored motivational drives that determine character actions
  • Finite State Machines: Multi-layered identity states with probabilistic transitions
  • Output Filtering: Multi-stage validation preventing moralizing, sanitization, and meta-commentary

Detailed Schema Breakdown

1. The Compilation Layer

Component Purpose Key Mechanisms
behavior_compiler Solves "Reference Leakage" problem
  • author_only_priors: Stores pop-culture references (never output)
  • reference_firewall: Lexical denylist + banned constructions
  • rewrite_protocol: Self-correction instructions
identity_axioms Hard-locked character identity
  • NOIR_IS_NOIR axiom
  • RAINEE_IS_RAINEE axiom
  • SHOW_DONT_CITE rule
output_filter Prevents AI sanitization
  • Meta-leak detector
  • Sanitization detector
  • Describe-don't-compare enforcement

2. The Agent Layer

Component Purpose Key Mechanisms
identity_fsm State-driven personality
  • Discrete psychological states
  • Probabilistic transition triggers
  • Prevents random trait blending
behavior_tree Decision-making logic
  • Selector/sequence nodes
  • Condition → Action mapping
  • Game-AI standard structure
utility_drives Motivational weighting
  • Numerical weights (0.0-1.0)
  • Priority-based action selection
  • Conflict resolution
voice_grammar Syntactic rules
  • Cadence patterns
  • Fillers and overuses
  • Vocabulary level

3. The Narrative Graph Layer

Component Purpose Key Mechanisms
emergent_events Probabilistic plot beats
  • Probability gates (0.0-1.0)
  • Prerequisite flags
  • Flexible sequencing
backstory_explanation Rough canon causal chain
  • Fixed cause-effect sequence
  • "Embellish freely" instruction
  • Canonical dialogue samples

4. The Thematic Layer

Component Purpose Key Mechanisms
story_themes Enforce comedic tone
  • Absurdity over tragedy
  • Commerce continues despite chaos
  • No lesson, no growth, no sanitizing
banned_modes Prevent AI failures
  • No moralizing
  • No very-special-episode sentimentality
  • No sanitized conflict resolution
scene_comedy_mechanics Comedic escalation
  • Escalation chains
  • Contrast engines
  • Theme checklist per scene

Why This Architecture Works

1. Decouples Identity from Mannerism

By separating identity_axioms (who they are) from voice_grammar (how they speak) and author_only_priors (where the inspiration came from), the LLM can generate highly specific, consistent voices without breaking the fourth wall.

2. Deterministic Comedy

Comedy in LLMs usually fails because the AI tries to resolve conflict or teach a lesson. The banned_modes and story_themes act as negative constraints, forcing the AI to escalate absurdity rather than resolve it.

3. State-Driven Consistency

The identity_fsm ensures that a character's reaction to stress is mathematically predictable (e.g., 90% chance to haggle, 70% chance to leak babyish indignation), preventing the "schizophrenic AI" problem where a character's personality shifts randomly from paragraph to paragraph.

4. Reference Firewall

The lexical_denylist and banned_constructions prevent the most common AI failure mode: describing characters by referencing their source material ("she acted like Stewie Griffin"). Instead, the AI must render the behavior natively using allowed_voice_tags and concrete action beats.

5. Anti-Sanitization

The sanitization_detector and explicit banned_modes prevent the AI from falling into "very-special-episode" moralizing, forced growth, or polite conflict resolution. Characters end every scene wanting MORE of what they already wanted.
